# Product document schema

`PRODUCT.md` is project-owned truth about what the product is and is not. A
harness may offer this schema as an initialization aid but must never update an
existing product document.

## Required sections

- Purpose
- Target user
- Core promise
- Primary workflows
- Product invariants
- Non-goals
- Supported platforms
- External integrations

Include only product commitments that are accepted and durable. Describe
unresolved questions in the roadmap or an explicit decision record rather than
presenting them as settled product truth.
