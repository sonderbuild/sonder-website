# Documentation lifecycle

Keep repository knowledge in the artifact that owns it: product promises and
non-goals in product documentation; technical structure and integration maps in
architecture documentation; outcome order in the roadmap; lasting choices in
decision records; and active complex work in execution plans.

When implementation changes durable reality, update the relevant artifact in
the same outcome. Do not rewrite product documentation merely to justify an
implementation, and do not preserve an obsolete plan or roadmap status for
historical convenience.

Periodically check for completed plans left active, multiple active primary
roadmap outcomes, decisions contradicted by current architecture, and duplicate
or stale documentation. Encode repeatedly discovered rules in tests, scripts,
schemas, or focused skills when practical.
